\section{Metodología de trabajo}

Para el desarrollo de este proyecto se ha empleado la metodología \textit{Cross-Industry Standard Process for Data Mining} (CRISP-DM). Ya que es una metodología especialmente pensada para proyectos de ciencia de datos y minería pensando en la evaluación de los resultados y múltiples iteraciones hasta conseguir una evaluación satisfactoria.

\subsection{Metodología CRISP-DM}

Esta metodología se desarrollo en 1996 gracias a varias empresas del sector de Tecnologías de la información y minería ya que estas necesitaban de un proceso estructura para este tipo de proyectos que hasta entonces no tenían una estructura clara. En 1997 gracias a un proyecto financiado por la Unión Europea en el marco del programa \textit{European Strategic Program on Research in Information Technology} (ESPRIT) cuyo fin era la creación de un procedimiento común entre diferentes industrias para la minería de datos. En el año 2000 fue cuando se presento su primera versión la cual es muy similar a la que conocemos actualmente \ref{fig:img-5} en el que vemos el  \cite{CrispDM} \cite{CrispDMWiki}.

En la figura \ref{fig:img-5} podemos ver el ciclo típico de esta metodología.
\imagen[0.6\textwidth]{img-5}{Foto de la metodología CRISP-DM}

Esta metodología esta basada en las fases de:

\begin{itemize}
\item Comprensión del negocio: Entender los objetivos del proyecto desde la perspectiva del negocio.
\item Comprensión de los datos: Recoger datos iniciales, explorarlos y evaluar su calidad para entender qué información puede ser útil.
\item Preparación de los datos: Transformar y limpiar los datos para que sean adecuados para el modelado.
\item Modelado: Aplicar técnicas estadísticas o de aprendizaje automático para crear modelos que respondan a los objetivos definidos.
\item Evaluación: Evaluar la calidad de los modelos, comprobar que realmente solucionan el problema del negocio.
\item Despliegue: Implementar el modelo en el entorno deseado y planificar su seguimiento y mantenimiento.
\end{itemize}


Para el desarrollo de este proyecto no se ha seguido la metodología CRISP-DM de manera estricta, la principal modificación que se ha realizado es que las iteraciones no volvían hasta la fase de comprensión de negocio sino que se volvía a partir de la fase de preparación de los datos. Además se incluye un último apartado que consiste en la finalización del documento asociado a la memoria de este proyecto.

\subsection{Fases del Proyecto}
Una vez que hemos decido emplear la metodología CRISP-DM distinguiremos las siguientes fases a lo largo del desarrollo del proyecto:

\begin{itemize}
\item Comprensión del negocio: esta fase esta centrada principalmente en entender los objetivos del negocio. En el caso de este proyecto esta etapa se ha centrado principalmente en comprender la idea que querían llevar a cabo los clientes con respecto al modelo de IA, de qué recursos disponía, así como, una investigación de los diferentes modelos de IA open-source que podrían valer para el objetivo del proyecto.

\item Comprensión de los datos: a continuación se necesita comprender que tipo de información disponemos para poder entrenar el modelo. El cliente facilitó una serie de documentos que contenían programas Java con el fin de emplearlos, por lo que esta será la base del conjunto de datos que se usarán para entrenar el modelo.

\item Preparación de los datos: en esta fase tras reconocer el tipo de datos de los que disponemos debemos de adaptarlos, con el fin de que el modelo escogido los reconozca y sea capaz de entenderlos correctamente para realizar un reentrenamiento correcto

\item Modelado: una vez se dispuso del conjunto de datos se creo el Jupyter Notebook con el código que permite el reentrenamiento del modelo de IA con el conjunto de datos previamente adaptado, con el fin de que el modelo resultante cumpla las expectativas del cliente.

\item Evaluación: en esta fase se centra en la evaluación propia del modelo con el fin de comprobar si este es capaz de cumplir con las expectativas pautadas por el cliente, a través de la evaluación propia del desarrollador y si los resultados eran validos, se pasaba a una valoración por parte del cliente con el fin de que el mismo comprobara los resultados. En este punto, como nos indica la propia metodología CRISP-DM, ha sido necesario varias veces volver a la fase de Preparación de Datos como veremos en la parte 2 de Desarrollo del trabajo.

\item Despliegue: Una vez se ha cumplido con una evaluación aprobada por el cliente el modelo se integra en un frontal adecuado para su uso y despliegue en entornos locales.

\item Finalización de la documentación y entrega del TFM: fase en la cual se revisa toda la documentación del proyecto para su entrega y presentación.

\end{itemize}

\section{Plan de Riesgos}

Para poder realizar un proyecto de cualquier índole es necesario elaborar un plan de riesgos. Estos riesgos deben de referirse a problemas futuros, los cuales podrían suceder durante el desarrollo del proyecto, y debe documentarse tanto la causa como el efecto que producirá el riesgo.


Para elaborar de manera correcta el plan de riesgos se han tenido en cuenta los siguientes puntos:

\begin{itemize}
    \item La probabilidad de que se produzca el riesgo. Será medida a través de los valores: bajo, medio y alto.
    \item El impacto que tendrá el riesgo. Si llega a aparecer será medido a través de los valores: bajo, medio y alto.
    \item Plan de mitigación: conjunto de acciones que se deben realizar para reducir la probabilidad de que un riesgo ocurra.
    \item Plan de contingencia: conjunto de acciones que se deben realizar una vez el riesgo se ha ocurrido para reducir su impacto sobre el proyecto.
\end{itemize}

 \end{itemize}
